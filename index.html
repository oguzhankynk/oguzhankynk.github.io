atlOS

An experimental x86_64 operating system in C++17, written to learn how one works: GRUB2 boot, paging, a kernel heap, a cooperative scheduler, ring 3 programs, FAT16 and a kernel shell. Its tutorial walks through the kernel in boot order.

gridlane

A layered, loosely coupled model for low-latency data distribution and messaging between processes and machines. Each process reads its data from local memory as if it were shared; the same binaries run over TCP across machines or over shared memory on one machine. Its layers are independent projects, each extensible with new APIs: pushseg (write far, read local), pairring (message channel) and wireforge (messages). A distributed Gray-Scott simulation demonstrates it end to end.

qemu-ntb

A virtual PCIe NTB (non-transparent bridge) for QEMU. Two VMs get what two hosts get from an NTB adapter: memory windows into each other's RAM, doorbells, scratchpads and a DMA engine, and the unmodified Linux NTB stack (ntb_transport, ntb_netdev, ntb_perf, the kernel selftest) runs on it. Memory windows can map the peer's RAM directly under KVM. Testing it turned up two Linux ntb_tool bugs and a QEMU migration bug, with fixes sent upstream. ntb-lab builds on it: a kernel module that gives ordinary programs shared memory, doorbells and DMA over NTB, with a two-VM tutorial.

VxWorks projects

Open-source tools for VxWorks 7, built and tested with the free VxWorks SDK on QEMU. vxworks_exporter is a Prometheus exporter: a kernel module that serves per-task CPU time, task states, stack usage, kernel heap and network counters, so a VxWorks target can be monitored in Prometheus and Grafana. tracy-vxworks brings the client of the Tracy profiler to VxWorks processes, with a demo that records a trace from VxWorks running in QEMU.
